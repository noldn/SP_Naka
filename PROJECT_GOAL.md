# Projektziel SP_Naka

## Zielbild

SP_Naka wird eine nachvollziehbare KI-gestützte Anwendung zur Datenanalyse. Das
Programm wird über Git versioniert und dokumentiert, verarbeitet aber lokale Daten,
ohne diese automatisch auf GitHub zu übertragen.

## Ziele

- Lokale Daten sicher einlesen und analysieren.
- Analyseschritte reproduzierbar und prüfbar machen.
- KI zur Unterstützung einsetzen, ohne ungeprüfte Ergebnisse zu übernehmen.
- Code, Entscheidungen und nicht vertrauliche Erkenntnisse systemübergreifend über
  Git verfügbar machen.
- Dokumentation so führen, dass sie später in ein Intranet übertragen werden kann.

## Nicht-Ziele der ersten Phase

- Keine Veröffentlichung echter Unternehmens- oder Personendaten auf GitHub.
- Keine vollautomatischen fachlichen Entscheidungen ohne menschliche Prüfung.
- Keine Festlegung auf ein KI-Modell oder eine Cloud-Plattform ohne Bewertung von
  Datenschutz, Kosten und Betriebsanforderungen.

## Geplante Ergebnisse

1. Ausführbare Anwendung für den lokalen Datenzugriff.
2. Validierte Analyse- und gegebenenfalls KI-Pipeline.
3. Automatisierte Tests mit synthetischen Daten.
4. Nachvollziehbare Architektur- und Entscheidungsdokumentation.
5. Aufbereitete Dokumentation für die spätere Intranet-Übernahme.

## Erfolgskriterien

- Eine neue Person kann das Projekt anhand des Repositorys einrichten.
- Lokale Daten können verarbeitet werden, ohne im Git-Verlauf zu erscheinen.
- Analyseergebnisse lassen sich mit dokumentierten Eingaben und Einstellungen wiederholen.
- Fachliche Aussagen enthalten Quellen, Annahmen und bekannte Einschränkungen.
- Relevante Projektentscheidungen sind über Git nachvollziehbar.

## Festgelegte Rahmenbedingungen

- Das GitHub-Repository `noldn/SP_Naka` ist privat.
- Auch ein privates Repository ist kein freigegebener Speicher für echte Rohdaten,
  Zugangsdaten oder ungeprüfte vertrauliche Inhalte.
- Die Analyse beginnt mit deterministischen Material- und Prozessregeln.
- Quantitative Toleranzen und Clustering werden erst nach fachlicher Definition und
  Validierung ergänzt.
- Ergebnisse werden begründet je Auftrag ausgegeben; Abweichungen werden zur
  manuellen Prüfung markiert.
- Manuelles Feedback darf neue Regelvorschläge erzeugen, Regeln aber nicht ohne
  fachliche Freigabe selbstständig verändern.
- Die finanzielle Zielgröße ist `Auftragskopf.Erlöse - Auftragskopf.Kosten` aus
  der bestehenden Nachkalkulation. Detailtabellen erklären und plausibilisieren
  das Ergebnis; sie ersetzen die Nachkalkulation noch nicht.
- Neue fertige Aufträge werden gegen einen historischen Referenzbestand in
  robusten, fachlich gestaffelten Peer-Gruppen verglichen.

## Noch zu entscheiden

- Welche Vertraulichkeitsstufen gelten im Unternehmen?
- Welche quantitative Schwankungsbreite ist je Material, Stufe und Auftragsart normal?
- Welche Merkmale und Clusterverfahren werden fachlich freigegeben?
- Welche Weboberfläche und Betriebsumgebung werden eingesetzt?
- Welche Inhalte dürfen später in welches Intranet übernommen werden?
